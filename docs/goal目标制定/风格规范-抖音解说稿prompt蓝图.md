# 抖音中文解说稿 — 风格规范 & Prompt 蓝图

> 本文档是"黄金样本→规范"的萃取结果，后续所有解说稿生成都围绕此规范。
> 参照样本：`project/英伟达黄仁勋播客/抖音剪辑版/抖音剪辑黄仁勋访谈口播稿_分段整理版.md`

---

## 一、核心转化规律（逐字稿 → 解说稿）

对照原文 SRT 与解说稿，发生了以下 6 层转化：

### 1. 钩子开场（Hook Opening）

**规律**：不从访谈第一句开始，而是摘取整场访谈中**最戏剧化的一个瞬间**作为开场，像电影预告片。

**样本分析**：
- 原文开头：`We've seen the valuations of a bunch of software companies crash...`（平淡提问）
- 解说稿开头：`"你这种输家心态我不能接受"，就在不久前，硅谷最火的一档科技播客的录影棚，黄仁勋...突然把声音给抬高了。`

**操作规则**：
- 扫描全文，找出情绪最激烈/观点最尖锐/冲突最明显的片段
- 用那个片段的高能瞬间作为开篇第一句
- 先制造悬念 → 再交代背景（谁、什么场合、为什么重要）

### 2. 解说者第一人称视角（Commentator Persona）

**规律**：不是中立旁白，而是有态度、有主观判断的"解说者"。类似体育解说 + 财经评论。

**样本分析**：
- "我也挺喜欢看他节目的" — 个人偏好
- "你想想这是什么场景" — 直接对观众说话
- "说实话，我认为，黄仁勋这个观点是对的" — 明确站队
- "这哥们儿什么来头" — 口语化、有性格

**操作规则**：
- 使用"你想想""说白了""你猜怎么着""说真的"等口语引导词
- 适当表达个人看法（"我觉得""我认为""说实话"）
- 对嘉宾/主持人可以有评价（"这哥们儿""这小伙子""不得不说"）
- 不要每段都出现，频率约每 300-500 字一次

### 3. 按主题/论点重组（Topic-Based Reorganization）

**规律**：完全打破原访谈的时间顺序，按**核心论点**重新分组。样本把 1.5 小时访谈重组成"四大赌注"结构。

**样本结构分析**：
```
开篇 Hook → 主持人背景介绍 → 开场提问（commoditization 争论）
→ 四大赌注：
  1. 供应链锁死（$95.2B → $250B）
  2. ASIC/TPU 竞争（Google、Broadcom、Amazon）
  3. 对华出口管制
  4. 产能天花板（N3 60% → N2 86%）
→ CUDA 护城河讨论 → 毛利与定价权 → Anthropic 失误
→ 芯片分配逻辑 → "beat-and-raise" 批评
→ 网络安全与中国政策 → 输家心态辩论
→ 英特尔错过 iPhone → 结语/收尾观点
```

**操作规则**：
- **不要顺着时间轴线性复述** — 这是最关键的差别
- 识别出 3-5 个核心论点/主题
- 每个主题下可以有多个 sub-points（正反观点对比）
- 主题之间需要有逻辑递进（而非时间顺序）
- 相关的原文片段跨时间轴聚合到同一主题下

### 4. 术语白话化（Jargon Translation）

**规律**：所有专业术语都翻译成大白话，并举例解释。

**样本映射表**：

| 原文术语 | 解说稿处理 |
|---|---|
| commodity / commoditize | "商品化，那就意味着它已经不值钱了，你就卖不出高价钱了" |
| fabless | "无晶圆厂的模式，意思就是，我们自己不开晶圆厂" |
| HBM | "就是给 AI 用的高速内存，像什么韩国的 SK 海力士，美国美光那几家在做" |
| CoWoS | "你理解成，把芯片和内存粘到一起的那种高级胶水，台积电独家的" |
| CUDA | "你就理解成，英伟达 20 年攒下来的一个语言系统" |
| token | "你跟 ChatGPT 聊天的时候，他一个一个蹦出来这些字、词、代码，每一个都是 token" |
| ASIC/TPU | "你就理解成为 Google 做的 TPU" |
| kernel | （通过 F1 赛车比喻解释，不直接翻译）|

**操作规则**：
- 每个专业术语第一次出现时必须用大白话解释
- 解释方式：类比（"相当于..."）、举例（"比如..."）、拆解（"意思是..."）
- 不要堆砌术语，宁可多花 2-3 句话讲透一个概念
- 解释完后可以继续用原文术语（观众已经懂了）

### 5. 穿插外部背景知识（Contextual Enrichment）

**规律**：主动补充访谈中没有的外部信息来增强可信度和深度。

**样本中的外部知识注入点**：
- 《芯片战争》一书 + Chris Miller 的历史分析
- ASML EUV 30 年研发史 + 2012 年客户入股故事
- 英特尔 CEO 保罗错过 iPhone 的采访细节
- 1986 年美日半导体协定 → 韩国三星崛起
- 电信行业封锁 → 华为中兴崛起的教训
- DeepSeek 2025 年初震动了硅谷后，2025-2026 年沉寂
- 独立分析师"卡卡西"的评论

**操作规则**：
- 在关键论点处补充 1-2 段外部知识（历史案例、行业数据、人物背景）
- 外部知识要服务于论述主线，不要为了炫学而离题
- 明确标注信息来源（"《经济学人》评价他...""《纽约客》给他的定位..."）
- 可以用类比帮助理解（"这有点像你玩魔兽..."）

### 6. 口语化、有节奏（Spoken-Word Rhythm）

**规律**：短句、设问、口头禅，适合口播。不是书面语。

**语言特征**：
- 短句为主（15-25 字），偶尔长句调剂
- 大量逗号断句（模拟口语停顿）
- 设问："那么问题来了""你猜怎么着""听明白了吧"
- 口语连接词："说白了""你看""就是说""你想"
- 强调重复："不是...不是...而是..."
- 数字可视化："300 亿美金什么概念，换成人民币是 2100 多亿"

**操作规则**：
- 每句话尽量不超过 30 字（中文）
- 用逗号模拟口语停顿，不是语法停顿
- 每 200-300 字来一个互动（设问/反问/呼告）
- 避免书面语的"首先...其次...最后"结构，改用"第一条...第二条..."
- 数字必须换算成观众能感知的量级

## 二、解说稿 Prompt 系统设计

基于以上 6 条规律，设计分层 prompt 策略：

### System Prompt（给 LLM 的核心约束）

```markdown
你是一个专业的抖音科技解说稿写手。你的任务是把播客访谈内容改写成适合口播的中文解说稿。

## 核心要求

1. **钩子开场**：不要从访谈第一句开始。从全文找出最戏剧化的冲突/观点作为开场，先制造悬念再交代背景。

2. **解说者视角**：你不是中立旁白，你是有态度的解说者。用"你想想""说白了""说真的"等口语引导词，可以评价嘉宾表现，可以表达自己的看法。

3. **按主题重组**：完全打破原访谈时间顺序，按核心论点（3-5个）重新组织内容。相关但分散在原文各处的片段要聚合。

4. **术语白话化**：每个专业术语第一次出现时必须用大白话解释（类比、举例、拆解）。解释完可以继续用原术语。

5. **外部知识补充**：在关键论点处补充历史案例、行业数据、人物背景等外部知识。标注信息来源。用类比帮助理解。

6. **口语化写作**：短句为主（每句不超过30字），用逗号模拟口语停顿。设问、反问、口头禅。数字要换算成观众能感知的量级。

## 风格参考

- 语言节奏参考体育解说 + 财经评论
- 每200-300字至少一次与观众互动（设问/反问/"你想"/"你看"）
- 可以用"这哥们儿""这小伙子""说白了"等口语表达
- 严肃分析和轻松表达交替出现，保持节奏感

## 格式要求

- 要有吸引人的标题（不是"某某访谈"这种，而是提炼核心冲突）
- 全文约2000-4000字
- 使用 Markdown 格式（但语言保持口语化）
- 不要保留任何"Speaker A/B"标签，全部用自然语言过渡
```

### User Prompt 模板

```markdown
以下是播客访谈的内容。请按抖音解说稿风格改写。

## 节目信息
- 标题：{title}
- 时长：{duration}
- 参与人：{speakers}

## 内容（已按主题分段，含说话人标注）

{thematic_sections}

## 输出要求

请生成一篇完整的抖音解说稿。要求：
- 钩子开场，不从第一句开始
- 按论点/主题重组（不要线性复述）
- 术语全部白话化
- 适当补充外部知识
- 口语化、有节奏、适合口播
- 字数：{target_words}字左右
```

## 三、质量检查清单（每篇产出自检）

对照黄金样本的 6 条特征逐条检查：

- [ ] **钩子开场**：是否跳过了访谈起始，用高能瞬间开场？
- [ ] **解说者视角**：是否有≥3处解说者主观表达/与观众互动？
- [ ] **主题重组**：是否打破了时间顺序？是否有 3-5 个清晰论点？
- [ ] **术语白话化**：所有专业术语是否都有大白话解释？
- [ ] **外部知识**：是否有≥2处外部知识补充（历史案例/数据/人物）？
- [ ] **口语化**：是否短句为主？是否有设问/口头禅？数字是否可视化？
