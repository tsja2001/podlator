# 工作文档：口播稿「长度翻倍 + 强模型定稿（Claude Code / Codex CLI）」

> 本文是交给**实现 AI** 的工作说明书。规划者只负责：可行性/政策结论、改动清单（高层）、**提示词设计（重点）**、**验收测试标准**。
> 具体代码实现细节由实现 AI 完成，本文不写完整代码。

---

## 1. 背景（为什么做）

当前抖音口播稿生成（`pipeline-douyin` / `douyin-script`）有两个不满意点：

1. **太短**：默认 `target_words=3000`，**单次** LLM 调用生成（[douyin_script.py:82](src/podlator/steps/douyin_script.py)），实际常欠量。目标：**做到现在的 2 倍（≈6000 字）**。
2. **最终输出想用更强的模型**：现在最终成稿走 `provider="claude"`，但那个 `claude` 是**第三方中转 API**（api.b.ai 的 claude-opus-4.7），不是用户本机用会员登录的 Claude Code。用户希望最终成稿由**本机 CLI 唤起的强模型**（`claude -p` 跑真·Opus / `codex exec` 跑 GPT-5）来写，质量更高。

**已确认的两个决策（用户拍板）：**
- **两个 CLI 都接，配置切换**：provider 抽象层同时支持 `claude_cli` 和 `codex_cli`，`.env` 一行切换。
- **两段式生成**：先用便宜模型（DeepSeek）出结构化「解说蓝图」，再由强 CLI 模型据蓝图**扩写+润色定稿**到 6000 字。

预期结果：一条命令产出约 6000 字、由官方 Opus / GPT-5 定稿的高质量口播稿。

## 2. 可行性 & 政策结论（给实现 AI 的约束）

**技术上完全可行，两家都官方支持非交互模式**（已查官方文档 + 本机已验证安装/登录）：
- `claude` v2.1.163，`~/.claude.json` 存在（会员已登录）。
- `codex` v0.137.0，`~/.codex/auth.json` 存在（会员已登录）。

**实现必须遵守的硬约束：**

1. **工作目录必须隔离**（最重要的坑）：两个 CLI 都会读「当前工作目录」的项目上下文——Claude 读 `CLAUDE.md`、Codex 读 `AGENTS.md`/config。**本仓库根有一份很大的 CLAUDE.md**，若直接在仓库里跑会把"编码助手"指令污染进口播稿。→ 必须在 `tempfile.mkdtemp()` 创建的**临时空目录**里运行子进程（`cwd=临时目录`）。
2. **Claude 不能用 `--bare`**：`--bare` 虽能跳过 CLAUDE.md，但它**强制要求 `ANTHROPIC_API_KEY`、不能用会员 OAuth**。走会员路线必须**不加 `--bare`**，改用「隔离 cwd」来避免上下文污染。
3. **认证走会员**：不要设置 API key 环境变量去覆盖；让 CLI 用本机已登录的会员态。
4. **计费心里有数**（不影响实现，但写进 README 提示用户）：
   - Anthropic 自 **2026-06-15** 起，`claude -p` 用量不再算进 Max 交互额度，改走独立月度 **Agent SDK 额度**（Pro \$20 / Max 5x \$100 / Max 20x \$200，用完按 API 价、不结转）。用户量级（月几期）远低于额度。
   - OpenAI `codex exec` 用量算进 **agentic 额度（5h 窗口 + 周配额）**，与交互式 Codex 共享。

## 4. ★ 提示词设计（本文重点）

两段式拆成两个 prompt 文件。沿用现有 `load_prompt(name)` 约定：每个文件用 `# System Prompt` / `# User Prompt` 两节，User 节用 `{占位符}`，由 `.format()` 注入。

### 设计思路（为什么这么拆）

单次让模型"写 6000 字"很不可靠——模型普遍欠量、容易注水。两段式把难点拆开：
- **Stage1 蓝图**：便宜模型擅长"读懂 + 拆结构"。先把全文拆成 3-5 个主题，每个主题预先备好"可展开材料"（佐证、待白话化术语、外部知识补充点），并**给每个主题分配字数预算**（各主题之和 ≈ 6000）。
- **Stage2 成稿**：强模型擅长"把骨架写成有声有色的中文口播稿"。它拿到的不是"写 6000 字"这种模糊目标，而是"5 个主题、每个 1200 字、材料齐备"——**分段字数预算让长度可达**，强模型负责质量。
- **字数补足回路**：成稿若仍欠量，带着草稿再唤起强模型续写补足（最多 2 轮）——长度的最终保险。

### 4.1 `src/podlator/prompts/douyin_blueprint.md`（Stage1：解说蓝图）

```markdown
# System Prompt

你是抖音科技解说稿的「结构策划」。你的任务**不是写成稿**，而是把一段英文播客访谈拆解成一份可执行的「解说蓝图」，供下游写作模型据此扩写成完整中文口播稿。

蓝图质量直接决定成稿能否写够字数、有没有信息增量。务必做到：
- 吃透全文，提炼真正有冲突、有信息量的内容，不要罗列流水账
- 为每个主题预留充足的「可展开材料」，下游要据此写出比原话多几倍的篇幅
- 主动标注需要白话化的术语、需要补充的外部背景
- 给出字数预算，各主题字数之和 ≈ 目标总字数

严格按下面的固定结构输出 Markdown。**不要写正文、不要写解说稿、不要任何寒暄。**

# User Prompt

请把下面这期播客访谈拆解成一份「解说蓝图」。

## 节目信息
- 标题：{title}
- 时长：约 {duration_minutes:.0f} 分钟
- 参与人：{speakers}
- 目标成稿字数：{target_words} 字

## 访谈内容（已标注说话人）

{content}

## 输出格式（严格遵守，逐项填写）

### 一、标题候选
给 3 个抖音风格标题（提炼核心冲突，每个 ≤25 字）。

### 二、钩子开场
指出全文最戏剧化 / 最反直觉的一个瞬间：谁、在什么场合、说了什么、为什么炸。用 2-3 句话说明这个开场怎么切入（不用写成稿）。

### 三、人物背景
- 主持人：身份、风格、为什么可信（要点式）
- 嘉宾：核心身份、为什么他的话有分量（要点式）
- 可引用的外部评价（如有）

### 四、核心论点（3-5 个，按口播逻辑递进排序）
每个论点填写：
- **标签**：一个鲜明的名字（如「四大赌注」「三层困境」）
- **核心观点**：一句话说清
- **访谈佐证**：原访谈里支撑它的关键信息（要点，可标大致时间点）
- **待白话化术语**：本主题的专业术语 + 一句话白话解释建议
- **外部知识补充点**：建议补充的访谈之外的背景/数据/案例（指明方向，下游落实）；全文这类点合计 **≥3 处**
- **字数预算**：本主题建议 ____ 字

### 五、字数预算汇总
列出各主题字数，确认总和 ≈ {target_words} 字。

### 六、结尾落点
建议用什么观点/金句收尾，给观众留下什么。
```

### 4.2 `src/podlator/prompts/douyin_finalize.md`（Stage2：据蓝图成稿）

> **System Prompt = 现有 [douyin_script.md](src/podlator/prompts/douyin_script.md) 的 System Prompt 全文（第 1–77 行，那 8 大核心要求 + 绝对禁止 + 风格 + 格式都保留）**，在其**末尾追加**下面两节。User Prompt 用下面的新版本。

```markdown
# System Prompt

<原 douyin_script.md System Prompt 第 1–77 行，原样保留>

## 本次任务：据蓝图扩写成稿
- 你会收到一份「解说蓝图」和原始访谈节选。蓝图是骨架，访谈是事实依据。
- 严格按蓝图的主题顺序和**字数预算**写，把每个主题**写满到它的预算**。
- 每个论点至少写透五层：① 抛出观点 → ② 访谈里的佐证/原话转述 → ③ 大白话解释清楚 → ④ 补一处外部背景/数据/案例 → ⑤ 你作为解说者的点评。五层都要落地，不能一笔带过。

## ⚠️ 字数纪律（硬约束）
- 目标 {target_words} 字，**低于 {min_words} 字视为不合格**。
- **严禁注水**：重复、套话、"总而言之"式凑字数一律禁止。
- 篇幅不够时靠**深挖**而非注水：举更具体的例子、做类比、补行业背景、对比同类案例、还原访谈现场细节、追问"这意味着什么"。
- 写完自检：每个主题是否达到了它的字数预算？没达到就继续展开。

# User Prompt

请根据下面的「解说蓝图」和原始访谈，写出完整的抖音中文解说稿。

## 节目信息
- 标题：{title}
- 参与人：{speakers}
- 目标字数：{target_words} 字（不得低于 {min_words} 字）

## 解说蓝图（你的写作骨架）

{blueprint}

## 原始访谈节选（事实依据，写作时据此佐证，不要逐字翻译）

{content}

## 输出要求（再次强调）
1. 直接从标题开始，**不要**任何 Meta 文字
2. **不用** ## / ### 标题，全程口语过渡
3. 按蓝图主题顺序展开，每个主题**写满字数预算**
4. **至少 3 处**外部知识补充
5. 每 300 字至少一次主观表达 / 与观众互动
6. 术语全白话化，数字可视化
7. 总字数 {target_words} 字左右，**低于 {min_words} 字不合格**
```

**新增占位符**：`{blueprint}`（Stage1 输出原样塞入）、`{min_words}`（= `int(target_words*0.9)`，由 step 计算后注入）。`content` 可复用 Stage1 同款截断文本。

### 4.3 字数补足回路（Stage2.5，可选但推荐）

成稿字数 < `min_words` 时触发。**System Prompt 沿用 4.2 的 finalize System**；User 用下面这段（占位符 `current_words`/`target_words`/`blueprint`/`draft`）：

```markdown
下面是已写好的解说稿草稿，当前约 {current_words} 字，距目标 {target_words} 字还差不少。
请在**不重复已有内容、不重写已有段落**的前提下，继续把篇幅补足到目标字数。

补充方式：挑蓝图里还没写透的主题 / 外部知识点继续深入，可在合适处插入更多例子、背景、点评。
**只输出新增的段落**（会被接到草稿后面），第一句用自然的口语过渡衔接，保持同样的风格。

## 解说蓝图
{blueprint}

## 当前草稿
{draft}
```

**回路规则**：最多 2 轮；每轮把新增段落追加到 draft 后再测字数；2 轮后仍不足则记 `WARNING`（带 `final_words`/`target_words`），**不报错**（返回已有成稿）。若发现"续写拼接"在口播时有割裂感，可改为"重写整稿到目标字数"的变体（更贵，质量更顺）——实现 AI 自行权衡，先做"续写"版。

## 5. 验收测试标准

### 5.1 功能验收（可自动化 / 半自动）
1. **默认字数翻倍**：不传 `--target-words` 跑 `pipeline-douyin`，成稿 **≥ 5400 字**（6000×0.9）。
2. **走了强模型**：日志里 Stage2 的 `provider` = `claude_cli` 或 `codex_cli`，且有 `duration_ms` + 成本字段（Claude 路径为真实 `cost_usd`；Codex 路径允许 `cost_usd=0` 但需 token 估算并注明）。
3. **两段都有日志**：blueprint 生成日志（provider/耗时）+ finalize 生成日志（字数/provider/cost）。
4. **cwd 隔离生效**：在仓库根目录跑，成稿中**不出现** CLAUDE.md 的编码术语（如 "DoD"、"LangGraph"、"pytest"、"节点装饰器"），证明没被项目上下文污染。
5. **两个 provider 都能切换**：`.env` 设 `llm_provider_polish=claude_cli` 与 `=codex_cli`，对同一期都能跑通并各自产出成稿。
6. **失败降级**：CLI 不存在 / 超时 / 非零退出时，降级到 API provider 并打 `WARNING`，pipeline 不崩。
7. **字数补足回路**：mock 一个 Stage2 故意写短的情况，验证补足被触发、最终 ≥ `min_words` 或 2 轮后打 `WARNING`。

### 5.2 质量验收（人工 review，≥1 期真实样本）
对照现有 8 大要求逐条核对：钩子开场 / 100–200 字人物介绍 / 第一人称解说 / 按 3–5 主题重组 / 术语白话化 / **≥3 处外部知识** / 短句口语 / 无 Markdown 标题 / 无 Meta 文字 / 无 Speaker 标签。并与旧版（3000 字 DeepSeek）对比：**长度≈2x，且信息增量与可读性不降反升**。

### 5.3 自动化测试（对齐 CLAUDE.md 第 9 章）
- **Unit**（mock `asyncio.create_subprocess_exec`，参考现有 transcribe 测试）：
  - `claude_cli` 成功：解析 JSON 拿 `result`/`cost`/`usage`
  - `codex_cli` 成功：解析 `-o` 输出文件 / stdout

  - 超时 → `ProviderError(retryable=True)`

  - **cwd 隔离**：断言子进程用的是临时目录而非仓库根

  - 字数补足：低于阈值触发、达标不触发、2 轮封顶

## 7. 留给实现 AI 的注意事项
- 不要用 `say` / 临时脚本替代 CLI；TTS 仍走外部 speech-transcriber（与本次无关）。
- Stage1 输入若超长（默认截断 30000 字符），可适当上调 `max_input_chars`；超长集数的 map-reduce 分块留作未来项，本次先不做。
- Stage2 单次调用 + 补足回路即可，**先不做按主题并发**（保持简单；如未来要并发再解析蓝图分段）。
- 措辞类（prompt 风格、标题口吻）属产品决策，定稿前找用户确认。
