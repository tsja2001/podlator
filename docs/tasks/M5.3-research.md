## 0. 背景与边界

差距分析认定「外部知识深度」是 v2 后最大剩余差距，而现状成稿里「《金融时报》报道过…」等引用**全部来自模型记忆，无任何验证**。本任务用 codex 的联网搜索把它做实。

**新链路**（本任务把 blueprint→finalize 拆开，中间插 research）：

```
digest(M5.2) → blueprint(step) → research(step) → finalize(step)
                    │                  │               │
              *.blueprint.md      *.research.json    输出
```

### 范围（明确不要做的事）

- ❌ **不做**审稿循环 / 修订 / 事实核查比对（M5.4）。research 只负责**产出**素材卡；finalize 是否忠实使用、有没有编造，由 M5.4 的 review 比对。
- ❌ **不改** digest（M5.2 已完成，只 `import` 它的产物）。
- ❌ **不动** rubric / judge / lint（M5.1）。
- ❌ **不在** unit/integration 调真实 codex；真实 search 只允许 1 次 smoke（见费用规约，codex 走会员额度**无现金成本**，但仍要门控+标注）。
- ⚠️ **codex `--search` 是顶层全局参数，必须放在 `exec` 之前**（`codex --search exec ...`）。放错位置会**静默失效**（不报错但不联网）——这是本任务最易踩的坑。

### 1.1 `src/podlator/steps/models.py`（追加）

```python
# -- Research 相关模型（M5.3）--


class ResearchFinding(BaseModel):
    """一条查证结果（带来源，可溯源）。"""

    claim: str  # 查到的事实陈述（中文）
    source_name: str  # 来源名（如 "SemiAnalysis" / "The Economist"）
    source_url: str  # 来源 URL
    published_date: str | None = Field(default=None)  # 发布日期（如有）
    confidence: Literal["high", "medium", "low"]


class ResearchCard(BaseModel):
    """一个研究问题的查证结果卡。"""

    question: str
    findings: list[ResearchFinding] = Field(default_factory=list)
    status: Literal["confirmed", "partial", "not_found"]


class ResearchDocument(BaseModel):
    """完整素材卡集合 — 落盘 *.research.json。"""

    schema_version: int = Field(default=1)
    source_blueprint: str | None = Field(default=None)
    cards: list[ResearchCard] = Field(default_factory=list)
```

## Phase 2: research step `src/podlator/steps/research_facts.py`（新建）

### 2.1 公开签名

```python
def extract_research_questions(blueprint: str) -> list[str]:
    """从 blueprint Markdown 的「研究问题清单」小节提取问题（每行一个 `- `）。
    找不到该小节 → 返回 []（不报错）。"""


async def research_facts(
    blueprint: str,
    *,
    provider_name: str | None = None,   # None → settings.llm_provider_research
    settings: Settings | None = None,
) -> ResearchDocument:
    """blueprint → 研究问题清单 → 逐条联网查证 → ResearchDocument。

    - 提取不到问题 → 空 ResearchDocument（正常返回）
    - 每条问题调 codex search（bounded 并发，_RESEARCH_CONCURRENCY=2，codex 子进程重）
    - 解析失败/单条超时 → 该问题 ResearchCard(findings=[], status="not_found")，不影响其它
    - 整步降级：provider 不存在(FileNotFoundError)/全部失败 → log.warning(
        "fallback_triggered", from_provider="codex_search_cli", reason=...) + 返回空 ResearchDocument
      research_facts 永不抛异常（pipeline 必须能继续）
    """


def format_research_for_prompt(research: ResearchDocument) -> str:
    """把 ResearchDocument 渲染成注入 finalize {research_cards} 槽位的文本。
    空集合 → 返回明确的「（无可用素材卡）」标记，让 finalize 进入宁缺毋滥模式。"""
```

### 2.2 内部

```python
async def _research_one_question(
    question: str, provider: LLMProvider, public_name: str
) -> ResearchCard:
    """调 codex search 查一个问题，解析 JSON → ResearchCard。
    失败 → ResearchCard(question, [], "not_found")。"""
```

实现要点：
- 用 `provider.complete(prompt, system=...)`（search 已在 provider 内启用）。prompt 要求**只输出 JSON**（ResearchCard 结构），解析复用 `evaluate_script._parse_json_block` 的剥离 + pydantic 校验 + 重试 1 次模式。
- `_RESEARCH_CONCURRENCY = 2` 用 `asyncio.Semaphore` 控并发。
- 日志：入口 `research_started`（问题数）；出口 `research_completed`（confirmed/partial/not_found 计数）；**不在循环里逐条 log**。
- `--output-schema` 强制 JSON 为**可选硬化**：baseline 先用「prompt 要求 JSON + 解析重试」（与项目其它 step 一致）；若 smoke 发现 codex JSON 合规性差，再在 `cli_tool.py` 的 codex 路径加 `--output-schema`（写临时 schema 文件）。**baseline 不做 schema 文件**，避免提前增加复杂度。

### 2.3 prompt `src/podlator/prompts/research_question.md`（新建）

````markdown
# System Prompt

你是事实核查研究员。你会拿到一个研究问题，请**联网搜索**后回答。

铁律：
1. 只报告你能在搜索结果里**找到来源**的事实，每条都要带来源名和 URL。
2. 找不到可靠来源的，**不要编造**——宁可少报。
3. **只输出一个 JSON 对象**，不要搜索过程、不要解释、不要 Markdown 代码块。结构：

{
  "question": "<原样回填问题>",
  "findings": [
    {"claim": "查到的事实", "source_name": "来源名", "source_url": "https://...",
     "published_date": "2024-03（如有，否则 null）", "confidence": "high|medium|low"}
  ],
  "status": "confirmed|partial|not_found"
}

status 规则：找到充分可靠来源=confirmed；只找到部分/弱来源=partial；查不到=not_found（findings 留空）。

# User Prompt

研究问题：{question}

请联网查证后只输出上述结构的 JSON。
````

## Phase 4: CLI —— pipeline 串入 research

### 4.1 `pipeline-douyin` 改为分阶段编排

`pipeline-douyin` 不再整体调用 `generate_douyin_script`，改为按 step 编排（research 要插在 blueprint 和 finalize 之间）：

```
[1/5] parse-srt
[2/5] assign-speakers（可 --skip-speakers）
[3/5] digest（按 --digest-mode，落盘 <output>.digest.json）        # M5.2 已有
[4/5] blueprint = generate_blueprint(...)  → 落盘 <output>.blueprint.md
[4.5] research = research_facts(blueprint) → 落盘 <output>.research.json   # 可 --no-research 关
[5/5] finalize_from_blueprint(..., research=research) → 写 <output>
```

新增选项：

```python
no_research: Annotated[bool, typer.Option("--no-research",
    help="跳过联网查证（外部知识进入宁缺毋滥模式）")] = False,
```

research 失败已在 step 内部降级为空 ResearchDocument，CLI 无需额外 try。每阶段 `typer.echo` 进度。
