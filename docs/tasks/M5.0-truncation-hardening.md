# M5.0 — 截断加固（消灭三个边界的静默截断）

> **执行者注意**：开始前先读 `docs/tasks/EXECUTION-FRAMEWORK.md`、`CLAUDE.md`（第 7、9、13 章）、`docs/tasks/M5-overview.md`。
> 本任务书包含所有设计决策。遇到未覆盖的情况，停下来在完成报告中说明，**不要自行猜测**。
>
> 一句话目标：把「静默截断」这个贯穿三处的隐藏 bug，从 provider 层装上**统一探测**（读 `finish_reason`），并把当前最直接受害的 `assign-speakers` 加固到不再丢标签；让所有截断从「悄悄丢数据」变成「一条可观察的 warning」。

---

## 0. 背景：这是一种病，出现在三个边界上

`docs/max-tokens-问题说明.md` 把问题讲成「DeepSeek 的 `max_tokens` 配小了」。真实情况是**同一种病在三个边界上发作**：

| 边界 | 在哪 | 现状 | 后果 | 谁负责 |
|---|---|---|---|---|
| **A. 输出截断（说话人）** | `assign_speakers.py` 硬编码 `max_tokens=8192`、`shard_size=80` | 分片 JSON 被截断 → `json.loads` 失败 → 整片返回 `{}` | 那一整片字幕**全丢说话人标签** | **本任务（M5.0）** |
| **B. 输出截断（定稿）** | `douyin_script.py` 的 `_complete_with_fallback` 调 `provider.complete(prompt, system)` **没传 max_tokens** | 走 CLI 没事；降级到 DeepSeek（8192）或 `claude` API（4096）时 6000 字定稿被腰斩 | 终稿结尾凭空消失，且只在降级时触发 | **M5.4**（重写 finalize 时） |
| **C. 输入截断（正文）** | `douyin_script.py` `DEFAULT_MAX_INPUT_CHARS=36000` | 40–75% 访谈正文被静默丢弃 | M5 头号问题 | **M5.2**（digest 改造） |

**本任务只做 A，外加一个三处共享的检测基础设施（finish_reason）。** B 和 C 各有归属，本任务**不许越界去碰**（见「范围」）。但本任务交付的 `finish_reason` 检测会被 B、C 以及 M5.1 的 judge 复用——这是为什么它先做。

**一个待验证的关键假设**：`deepseek-v4-flash` 可能是带思维链（reasoning）的模型，若如此，`max_tokens` 会把推理 token 一起算进去，那「减小分片」帮助有限、真正要调的是 `max_tokens` 本身。这点**不能凭记忆断定**，Phase 4 用一次真实 smoke 验证。好在本任务的修法（finish_reason 检测 + 显式合理 max_tokens + 减小分片 + 部分 JSON 抢救）对两种成因都成立。

## Phase 1: provider 层 finish_reason 检测（三处共享的地基）

**设计原则**：截断的「静默」来自没人读 `finish_reason`。OpenAI 兼容响应里 `choices[0].finish_reason == "length"` 是「我被截断了」的权威信号。把它读出来、塞进 `LLMResult`、并在截断时 `log.warning`——一处改动，A/B/judge 全受益。

### 1.1 `LLMResult` 增加 `finish_reason` 字段

`src/podlator/providers/llm/base.py`：

```python
@dataclass
class LLMResult:
    """LLM 调用结果。"""

    content: str
    model: str
    provider_name: str
    tokens_in: int
    tokens_out: int
    duration_ms: float
    cost_usd: float
    finish_reason: str | None = None   # "stop" | "length" | None（CLI 无元数据时）
```

> 放在**最后**且带默认值 `None`：现有所有构造点都用关键字参数，加默认字段向后兼容，不破坏旧测试。

### 1.2 DeepSeek / Claude provider 读取并告警

`src/podlator/providers/llm/deepseek.py` 和 `claude.py` 同样改法。以 DeepSeek 为例：

```python
# create() 调用前先把实际生效的上限存下来，告警时要带上
effective_max_tokens = max_tokens or self.default_max_tokens
response = await self.client.chat.completions.create(
    model=self.model,
    messages=messages,
    temperature=temperature,
    max_tokens=effective_max_tokens,
)
...
choice = response.choices[0]
finish_reason = choice.finish_reason          # "stop" / "length" / ...
content = choice.message.content or ""
...
if finish_reason == "length":
    log.warning(
        "llm_output_truncated",
        provider="deepseek",
        model=self.model,
        finish_reason=finish_reason,
        max_tokens=effective_max_tokens,
        tokens_out=tokens_out,
        hint="增大 max_tokens，或减小输入/分片",
    )

return LLMResult(
    content=content,
    model=self.model,
    provider_name="deepseek",
    tokens_in=tokens_in,
    tokens_out=tokens_out,
    duration_ms=duration_ms,
    cost_usd=cost,
    finish_reason=finish_reason,
)
```

`claude.py` 同样：存 `effective_max_tokens`、读 `finish_reason`、`== "length"` 时 `log.warning("llm_output_truncated", provider="claude", ...)`、`LLMResult(..., finish_reason=finish_reason)`。

### 1.3 CLI provider 尽力透传（容错，不强求）

`src/podlator/providers/llm/cli_tool.py`：

- **Claude 路径**：`stop_reason = result_json.get("stop_reason")`（Claude CLI 的 JSON 可能含此字段，**缺失时为 None，不要因缺字段报错**）。映射：Claude 的 `stop_reason == "max_tokens"` 视为截断 → `log.warning("llm_output_truncated", provider="claude_cli", finish_reason=stop_reason, ...)`。`LLMResult(..., finish_reason=stop_reason)`。
- **Codex 路径**：`-o` 输出文件是纯文本、无元数据 → `finish_reason=None`，不告警。

> CLI 路径本就不传 max_tokens 上限（claude CLI 不加 `--max-tokens` 时用其自身默认、codex 忽略），是三条路里最不容易截断的。这里只做「能读就读」，不为它增加复杂度。

### 2.2 `_parse_llm_content` 增加「部分 JSON 抢救」

截断的现象是 `{"index": 74, "speaker": "PA`——JSON 整体 parse 失败，但前面 73 条是完整的。现状一失败就整片丢；改成：parse 失败时用正则抢救所有**完整**对象。

```python
import re

# 匹配一个完整的 {"index": N, "speaker": "X"} 对象（容忍空白）
_SPEAKER_OBJ_RE = re.compile(
    r'\{\s*"index"\s*:\s*(\d+)\s*,\s*"speaker"\s*:\s*"([^"]*)"\s*\}'
)

def _parse_llm_content(content: str) -> dict[int, str] | None:
    clean = content.strip()
    if clean.startswith("```"):
        lines = clean.split("\n")
        clean = "\n".join(lines[1:-1] if lines[-1].strip() == "```" else lines[1:])

    try:
        assignments = json.loads(clean)
    except json.JSONDecodeError:
        # 截断抢救：正则提取所有完整对象，能救多少救多少
        salvaged = {int(idx): spk for idx, spk in _SPEAKER_OBJ_RE.findall(clean)}
        if salvaged:
            logger.warning(
                "assign_speakers_salvaged_partial_json",
                recovered=len(salvaged),
                content_preview=content[:200],
            )
            return salvaged
        logger.warning(
            "assign_speakers_parse_failed",
            content_preview=content[:200],
        )
        return None
    # ... 原有 isinstance(list) 校验与 speaker_map 构建逻辑不变 ...
```

> 注意：保持原有「合法但非 list」「合法 list」的分支不变；只在 `JSONDecodeError` 分支插入抢救。

## Phase 3: config 默认值 + .env.example

**目的**：抬高 API provider 的默认输出上限，让 B 边界的降级路径（M5.4 之前的过渡期、以及任何走 DeepSeek/Claude API 的调用）不再被 8192/4096 卡死。**这是地基，不是 B 的完整修复**——B 的完整修复（finalize 按 target_words 显式传 max_tokens）在 M5.4。

### 3.1 `src/podlator/config.py`

```python
# ── DeepSeek（OpenAI 兼容 API）──
deepseek_max_tokens: int = 32768   # 从 8192 提到 32K：覆盖 6000 字定稿(≈12K token)+余量
#                                    （V4-Flash 真实上限 384K；不设那么高，避免 prompt 出 bug 时狂输出浪费）

# ── Claude（第三方平台，OpenAI 兼容 API）──
claude_max_tokens: int = 8192      # 从 4096 提到 8192：4096 连一篇定稿都装不下
#                                    （M5.4 会在 finalize 调用处按 target_words 显式覆盖）
```

### 3.2 `.env.example`
