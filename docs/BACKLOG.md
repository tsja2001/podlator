## B2 — 发布配套物自动生成

**一句话**：每期的播客标题、简介、开场白、来源声明，从手写变成自动出草稿。

**现状**：`播客meta.md` 和 `开场文案.md` 每期手动整理（约 20–30 分钟纯机械劳动），但素材其实早就有——蓝图里已产出「标题候选 ×3」和「钩子开场」，终稿开头三句几乎就是开场白。

**做法要点**：
- 新增 step：输入 = 蓝图 + 终稿 + 期数，输出 = `播客meta.md` + `开场文案.md`，格式对齐第 08 期的现有模板（标题带 `No.XX 英文播客精读：` 前缀、简介含"非逐字翻译"声明、来源说明含原视频链接）
- 实现路径已有现成方案：`docs/CODEX_CLI_NON_INTERACTIVE.md` 第 3 节给出了 `codex exec --output-schema` 生成 meta JSON 的完整模板（title/description/opening 三字段 schema），直接照用
- 原视频链接需要用户提供或从 SRT 同目录的下载记录推断——CLI 加 `--source-url` 参数
- 开场白模板化后与 D1 节目化资产联动（固定的"欢迎收听"句式从 `series.md` 读取）

**前置依赖**：M5.4 链路稳定（meta 生成挂在 pipeline 末尾）。
**预估工作量**：半天（一个 step + prompt + 测试）。

## B3 — TTS-ready 化（听感最后一公里）

**一句话**：稿子最终是**听**的，但当前没有任何环节为 TTS 优化；在文本→音频之间加一道「听感处理」。

**问题清单**（来自第 12 期实稿观察）：
- **英文术语裸读**：满篇 H100、CoWoS、NCNR、Alchian-Allen、neocloud、AGI-pilled——火山引擎 TTS 读英文缩写的效果未经验证，可能是最大的听感坑
- **数字读法**："1.40美元"（一点四零？一块四？）、"8760小时"、"$95.2B" 等格式 TTS 读法不可控
- **句子节奏**：当前稿子几乎每句一行的碎片短句，TTS 朗读时停顿是否自然待验证（rubric v3 已把"单调碎片化"列入扣分项，部分缓解）
- **同音字/拗口组合**：连续同音字堆叠影响听感

**做法要点**：
- 新增「TTS 预处理」step：英文术语按映射表转写或保留（映射表放 `series/glossary.md` 扩展列，与 D1 联动：术语 → 中文读法/保留英文）；数字规整为读法友好格式；输出 `*.tts.md`
- 分段输出：开场 / 正片切开（当前手动切），直接对接 `speech-transcriber synthesize` 的两次调用
- 进阶：一条命令完成 TTS 调用 + ffmpeg 拼接。**注意**：speech-transcriber 项目路径在两台机器上不同（`/Users/mac/Project_Personal/...` vs `/Users/yangzhuoran/program/...`），必须做成 `.env` 配置项而非硬编码
- 验证方式：先人工抽听——挑一段术语密集的稿子，原文 vs 预处理后各合成 30 秒对比

**前置依赖**：无硬依赖，随时可做；与 D1 的 glossary 联动后更顺。
**预估工作量**：映射表 + 预处理 step 一天；TTS 一键串联再加半天（涉及外部项目调用约定，见 CLAUDE.md 手动 TTS 工作流的约束）。

## D2 — 订阅化（内容找你，而不是你找内容）

**一句话**：监控常听的频道/播客源，新内容自动产出「蓝图 + 选题评估」，你早上从候选里挑，批准的才跑完整链路。

**做法要点**：
- 源监控：yt-dlp 拉 YouTube 频道/播放列表新条目（Dwarkesh 等），或 RSS feed；定时任务（launchd / cron）
- 自动跑轻量链路：拉字幕 → parse → digest → blueprint（全部便宜模型，单期成本 ¥1 以内）
- 选题评估 prompt：基于蓝图输出「这期值不值得做」——信息密度、与往期选题重合度（查 `series/episodes.md`）、嘉宾分量，给出 推荐做 / 一般 / 跳过 + 一句话理由
- 产出形式：每天一份 `inbox/YYYY-MM-DD.md` 候选清单（标题 + 评估 + 蓝图链接），你看完挑选；批准 = 跑 finalize + review 的完整链路
- 关键设计：**昂贵环节（强模型 finalize、研究、审稿循环）只在人工批准后触发**，监控和蓝图层保持低成本常开

**前置依赖**：M5 全链路稳定 + D1 的 episodes.md（选题查重需要）。
**为什么暂缓**：交互模式的改变值得先想清楚——目前"自己挑内容"本身是编辑判断的一部分，自动化它之前先用 M5 把单期质量做到顶。
