# 评分体系进化规范

> 目的：让口播稿评分标准（rubric）成为一个**可进化的资产**——你每次刷到优秀的解说视频/播客，都能把它的优点萃取进评分体系，而不破坏已有的校准。
>
> 当前版本：rubric v3（`src/podlator/prompts/rubric_v3.md`，M5.1 落地）。
> 本文档由规划者维护，操作主体是统筹者（你）+ 任意 AI 助手。

---

## 1. 核心设计：三个解耦

理解了这三个解耦，进化就是安全的：

1. **rubric 与 judge 代码解耦**：评分标准是独立的 `rubric_vN.md` 文件，judge prompt 在运行时注入它。**改标准永远不需要改代码**，只需要新增一个版本文件。
2. **版本不可变**：`rubric_v3.md` 一旦投入使用就不再修改内容。任何改动 → 复制为 `rubric_v4.md` 再改，文末写变更记录。这样任何历史评分报告（`*.review.json` 里记录了 `rubric_version`）都可追溯当时用的是哪套标准。
3. **校准集与标准解耦**：校准集（带人工评分的样本库）是独立资产，用来验证"新标准下 judge 的判断仍与人的判断一致"。标准可以进化，但每个新版本都必须通过同一道校准关。

## 2. 资产目录约定

```
eval/
├── golden_samples/              # 黄金样本库
│   └── <样本名>/
│       ├── script.md            # 解说稿全文（自己转写或整理）
│       ├── meta.md              # 来源：视频链接、作者、收录日期、为什么收录（一句话）
│       └── human_score.md       # 人工评分（按现行 rubric 逐维打分 + 总评）
└── calibration.md               # 校准集清单：样本 → 人工总分 → 期望排序关系
```

初始校准集 = M5.1 用的 4 个样本（黄仁勋黄金样本 + Musk/Casey/Nielsen v2 产出）。

**校准集纪律**：
- 每个入库样本必须有人工评分（这是"锚"，没有人评的样本不进校准集）
- 校准集控制在 **6–10 个**：太少没有区分度，太多人工评分维护不动
- 保持分数梯度：库里要始终有高分（90+）、中分（75–88）、低分（<70）三档样本，否则 judge 的区分度无法验证

## 3. 新黄金样本接入流程（五步）

当你看到一个非常优秀的解说视频/口播内容时：

### 第 1 步 — 采集
拿到文字稿（下载字幕，或音频转写后整理），存入 `eval/golden_samples/<样本名>/script.md`，填好 `meta.md`。

### 第 2 步 — 萃取（用 AI，prompt 模板见第 5 节）
让 AI 对照**现行 rubric** 分析这个样本，回答三个问题：
1. 按现行 rubric 打分，它得多少分？（如果它明明很优秀却打不出高分 → 标准有盲区）
2. 它有哪些打动人的手法是现行 rubric **捕捉不到**的？（候选新锚点 / 新维度）
3. 它有没有现行 rubric 会奖励、但其实是缺点的地方？（候选反例，写进锚点的扣分描述）

产出一份「萃取报告」，存到该样本目录下。

### 第 3 步 — 修订（人做决策）
你读萃取报告，决定哪些发现值得纳入标准。修订方式按影响从小到大：
- **改锚点措辞**：在某档分数描述里增加正例/反例（最常见，优先用这种）
- **调维度权重**：某维度满分增减（同步调其他维度保持总分 100）
- **新增维度**：最重的改动，先走「影子计分」（见第 4 节红线）

复制 `rubric_vN.md` → `rubric_v(N+1).md`，落实修订，文末写变更记录（改了什么、依据哪个样本）。

### 第 4 步 — 回归校准
新版本必须通过与 M5.1 相同的校准关：

```bash
# 对校准集的每个样本用新 rubric 评分
uv run podlator eval eval/golden_samples/<每个样本>/script.md --rubric v4
```

通过条件：
- judge 排序与人工排序一致（人工分差 ≤2 分的样本对，不要求 judge 区分先后）
- 高低分样本的分差 ≥8（区分度不塌）
- 新收录的样本本身在新标准下得到与你人评相符的分数

**回归不过 → 回到第 3 步调锚点措辞，不准带病上线。**

### 第 5 步 — 生效与归档
- 把日常生成链路的默认 rubric 版本切到新版（M5.4 之后审稿循环也用它）
- 新样本连同人工评分加入校准集（如果超过 10 个，淘汰一个信息量最低的旧样本——通常是与其他样本分数和风格都接近的那个）
- 旧 rubric 文件保留不删

## 4. 红线（防止进化变成漂移）

1. **改 rubric 必跑回归**，没有例外。校准是评分体系的"测试套件"——这和代码改动必跑 pytest 是同一个纪律。
2. **新维度先影子计分**：新增维度的头 1–2 期，judge 照常给该维度打分但**不计入 total_score**（写进 rubric 时标注「影子维度」）。观察它的打分是否稳定、是否与你的直觉一致，再转正计分。
3. **一次只进化一步**：不要在同一个版本里同时新增维度 + 调权重 + 改多处锚点。小步进化，每步可回滚。
4. **样本优先于理论**：每条锚点修订都应该能指着某个具体样本说"因为它"。凭空想出来的标准不收。
5. **警惕风格单一化**：如果收录的黄金样本全是同一个创作者的，rubric 会进化成"模仿他"。刻意收录不同风格的优秀样本（科技解说、财经评论、科普叙事），让标准描述"什么是好"而不是"像谁"。

## 5. 萃取 prompt 模板（直接复制使用）

```text
你是内容评分体系的研究员。下面给你一份「口播稿评分标准 rubric vN」和一篇被人工认定为优秀的解说稿样本。

任务（按顺序输出三部分）：

一、按 rubric 逐维打分
对样本按 rubric 打分，每维引用样本原文作为证据。最后给总分。

二、盲区分析（最重要）
列出这篇样本中真正打动人、但现行 rubric 捕捉不到或奖励不足的手法。
每条包含：
- 手法描述（它做了什么）
- 样本原文证据（引用）
- 建议落点：改哪个维度的哪档锚点措辞 / 还是值得新增维度（给出建议的锚点描述草稿）

三、反向检查
列出 rubric 会给分、但这篇样本刻意避免了的做法（说明高手为什么不这么做）。
每条给出建议的扣分锚点措辞。

注意：
- 你的产出是「评分标准修订建议」，不是稿件修改建议
- 建议必须具体到锚点措辞级别，能直接抄进 rubric
- 宁可少而准，不要罗列泛泛的优点

## rubric vN 全文
<粘贴 src/podlator/prompts/rubric_vN.md>

## 优秀样本全文
<粘贴 script.md>
```

## 6. 与生成链路的关系（M5 全景中的位置）

- **M5.1**：rubric v3 + judge + `podlator eval`（评分能力本身）
- **M5.4**：审稿循环在生成时消费 judge 的 `revision_directives`（评分能力接入生产）
- **本规范**：评分能力的**长期维护协议**——你每收录一个新黄金样本，整条生成链路的质量天花板就抬高一格，因为审稿编辑（judge）的眼光变高了，它会把更高的要求通过修订指令传导给写手。

这就是这套体系的复利逻辑：**你不再直接调 prompt 措辞，而是通过喂样本来进化"什么是好"的定义，让系统自己向它看齐。**
