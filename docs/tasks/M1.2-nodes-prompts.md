### 1.4 创建 Prompt 加载工具

在 `src/podlator/prompts/__init__.py` 中：

```python
"""Prompt 模板加载工具。"""
from __future__ import annotations

from pathlib import Path


PROMPTS_DIR = Path(__file__).parent


def load_prompt(name: str) -> tuple[str, str]:
    """加载 prompt 模板，返回 (system_prompt, user_prompt_template)。
    
    模板文件用 '# System Prompt' 和 '# User Prompt' 分隔。
    """
    path = PROMPTS_DIR / f"{name}.md"
    content = path.read_text(encoding="utf-8")
    
    # 按 "# User Prompt" 分割
    parts = content.split("# User Prompt")
    system = parts[0].replace("# System Prompt", "").strip()
    user_template = parts[1].strip() if len(parts) > 1 else ""
    
    return system, user_template
```

**Provider 注入方式：**
节点需要访问 Settings 来创建 Provider。两种方式：
- **方式 A**：节点内部 `Settings()` 创建配置 → 简单但不够可测
- **方式 B**：通过 state 传入 provider 或 settings → 更可测

推荐方式 B：在 state 中加一个 `_settings` 字段（以下划线前缀表示运行时注入，不持久化），
或者在 `build_graph()` 时通过 LangGraph 的 config 机制注入。

**最简单的做法（M1 先用）**：节点内部创建 Settings + Provider。M3 再重构为依赖注入。

```python
@node("fetch_metadata")
async def run(state: PodlatorState) -> dict[str, Any]:
    log = node_logger(state, "fetch_metadata")
    
    settings = Settings()
    downloader = get_downloader(settings)
    
    metadata = await downloader.fetch_metadata(state["source_url"])
    
    log.info("metadata_fetched", title=metadata.title, duration_seconds=metadata.duration_seconds)
    
    return {
        "title": metadata.title,
        "description": metadata.description,
        "duration_seconds": metadata.duration_seconds,
        "published_at": metadata.published_at,
        "source_type": metadata.source_type,
        "thumbnail_url": metadata.thumbnail_url,
    }
```

## Phase 3: LLM 节点实现（chapter_split + summarize_chapters + polish_final）

### 3.1 实现 `src/podlator/graph/nodes/chapter_split.py`

**逻辑：**
1. 加载 prompt 模板：`load_prompt("chapter_split")`
2. 用 state 中的数据填充 user prompt：`user_prompt.format(duration_seconds=..., transcript_text=...)`
3. 调用 DeepSeek LLM：`provider.complete(prompt=user, system=system)`
4. 解析返回的 JSON（`json.loads(result.content)`）
5. 将 JSON 章节列表转为 `list[Chapter]`：
   - 根据每个章节的 `start`/`end` 找到对应的 `segment_indices`
   - `summary_zh` 暂时为空字符串（下一个节点填充）
6. 返回 `{"chapters": chapters}`

**JSON 解析容错：**
- LLM 可能在 JSON 前后加文字说明，用正则提取 `[...]` 部分
- 解析失败 → `NodeError("chapter_split", "Failed to parse chapters JSON", retryable=True)`

```python
import json
import re

def extract_json_array(text: str) -> list:
    """从 LLM 输出中提取 JSON 数组。容忍前后有其他文字。"""
    match = re.search(r'\[.*\]', text, re.DOTALL)
    if not match:
        raise ValueError("No JSON array found in LLM output")
    return json.loads(match.group())
```

### 3.2 实现 `src/podlator/graph/nodes/summarize_chapters.py`

**逻辑：**
1. 加载 prompt 模板：`load_prompt("summarize_chapter")`
2. **并发处理**：对每个 chapter 并行调用 LLM
   ```python
   import asyncio
   
   tasks = []
   for chapter in state["chapters"]:
       chapter_text = get_chapter_text(state["transcript_segments"], chapter)
       user = user_template.format(
           chapter_title=chapter["title"],
           start=chapter["start"],
           end=chapter["end"],
           chapter_text=chapter_text,
       )
       tasks.append(provider.complete(prompt=user, system=system))
   
   results = await asyncio.gather(*tasks, return_exceptions=True)
   ```
3. 处理结果：成功的填入 `summary_zh`，失败的记录日志但继续
4. 返回更新后的 `chapters` 和 `chapter_summaries`

**辅助函数**：
```python
def get_chapter_text(segments: list[TranscriptSegment], chapter: Chapter) -> str:
    """拼接章节对应的转录片段文本。"""
    chapter_segments = segments[chapter["segment_indices"][0]:chapter["segment_indices"][-1] + 1]
    return " ".join(seg["text"] for seg in chapter_segments)
```

**并发控制**：DeepSeek V4-Flash 应该没有严格的 rate limit，但可以用 `asyncio.Semaphore(5)` 限制并发数以防万一。

### 4.1 实现 `src/podlator/graph/nodes/export_markdown.py`

**逻辑：**
1. 从 state 获取 `brief_markdown`, `task_id`, `title`
2. 创建输出目录 `data/briefs/{task_id}/`
3. 将 title 转为安全文件名（去掉特殊字符）
4. 写入 Markdown 文件
5. 返回 `{"output_path": str(file_path)}`

```python
import re
from podlator.storage.paths import get_brief_dir

def slugify(text: str) -> str:
    """将标题转为安全的文件名。"""
    text = re.sub(r'[^\w\s-]', '', text)
    return re.sub(r'[-\s]+', '-', text).strip('-')[:80]
```

### 4.2 实现 `src/podlator/graph/nodes/diarize.py`

**M1 阶段的 diarize 节点是"跳过"逻辑**：
- 检查 `state.get("has_diarization", False)`
- 如果已有说话人标签 → 直接返回空 dict（不做任何事）
- 如果没有 → 暂时也返回空 dict + 警告日志（M4 才实现 pyannote）

```python
@node("diarize")
async def run(state: PodlatorState) -> dict[str, Any]:
    log = node_logger(state, "diarize")
    
    if state.get("has_diarization", False):
        log.info("diarization_skipped", reason="STT already provided speaker labels")
        return {}
    
    log.warning("diarization_not_implemented", reason="M4 will implement pyannote.audio")
    return {}
```

### 4.3 更新 builder.py

将线性的 Graph 改为带条件分支：
- `transcribe` 之后检查 `has_diarization`
  - `True` → 跳过 `diarize`，直接到 `chapter_split`
  - `False` → 经过 `diarize` 再到 `chapter_split`

```python
def should_diarize(state: PodlatorState) -> str:
    """条件路由：是否需要说话人分离。"""
    if state.get("has_diarization", False):
        return "chapter_split"
    return "diarize"

# 在 build_graph() 中：
graph.add_conditional_edges("transcribe", should_diarize, {
    "chapter_split": "chapter_split",
    "diarize": "diarize",
})
graph.add_edge("diarize", "chapter_split")
```
