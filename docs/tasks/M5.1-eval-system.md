### 1.1 创建 `src/podlator/prompts/rubric_v3.md`

**将下面的 rubric 全文原样写入该文件**（这是产品资产，独立于 judge prompt 存放，便于后续版本进化时不动代码——见 `docs/EVAL_EVOLUTION.md`）：

````markdown
# 口播稿评分标准 v3

> 版本：v3（2026-06）。变更记录见文末。满分 100。
> 适用对象：英文播客访谈 → 中文口播解说稿。
> 使用方式：由 judge prompt 注入，逐维打分；每个分数必须引用稿件原文作为证据。

## 内容组（45 分）

### 1. 信息覆盖度（20 分）
稿件是否覆盖了原访谈全程的核心论点（依据「参照论点清单」判断；若无参照清单则本维不计分，总分按比例折算到 100）。
- 18–20：覆盖 ≥85% 核心论点，访谈后半段的论点有充分呈现
- 14–17：覆盖 70–85%，后半段有涉及但偏薄
- 10–13：覆盖 50–70%，内容明显偏重访谈前半部分
- 5–9：只覆盖前 1/3 的论点，后段几乎缺失
- 0–4：大量论点缺失，或存在参照清单之外的杜撰论点

### 2. 信息忠实度（10 分）
访谈观点转述是否准确：无歪曲、无张冠李戴（A 的观点安到 B 头上）、数字与原文一致。
- 9–10：抽查的观点与数字全部忠实，立场归属清晰
- 7–8：个别表述简化过度但不歪曲原意
- 4–6：有 1–2 处明显歪曲或数字错误
- 0–3：多处歪曲，或关键论点张冠李戴

### 3. 外部知识质量（15 分）
访谈之外补充的背景知识（历史案例、行业数据、人物故事）的数量、深度与可信度。
- 13–15：≥3 处，且至少 1 处有「产业史诗感」的深度叙事（如 ASML 30 年研发史级别的展开），全部标注来源且服务论述主线
- 10–12：≥3 处且标注来源，但多为一句话数据，缺深度叙事
- 6–9：1–2 处，或有补充但来源标注缺失
- 3–5：外部知识极少，且与主线关联牵强
- 0–2：无外部知识，或存在明显编造痕迹（无法对应任何真实来源的具体引用）

## 叙事组（30 分）

### 4. 钩子开场（10 分）
- 9–10：以全片最高能的冲突/反直觉瞬间开场，3 秒内制造悬念，随后才交代背景
- 7–8：有冲突瞬间但铺垫稍长，或悬念强度一般
- 5–6：设问式平开（"你见过…吗"类），无具体冲突场景
- 3–4：以背景介绍开场（先讲这是什么节目/嘉宾是谁）
- 0–2：从访谈第一句开始线性进入

### 5. 结构与递进（12 分）
- 11–12：3–5 个核心论点 + 鲜明标签（如"四大赌注"），论点间逻辑递进，跨时间轴聚合原文素材，结尾有收束落点
- 8–10：论点清晰但标签平淡，或递进关系较弱
- 5–7：有分主题但接近原访谈时间顺序，聚合度低
- 2–4：基本线性复述，主题边界模糊
- 0–1：流水账
（注意：结尾收束后不应再出现游离的追加段落——若发现"结尾之后还有结尾"，扣至 8 分以下并在 issues 中注明。）

### 6. 人物与现场感（8 分）
- 7–8：主持人/嘉宾背景讲成有细节的故事（身份、可信度、外部评价），并在关键转折处回访"这场访谈"的现场（语气、反应）
- 5–6：有人物介绍但偏履历罗列；现场感偶有出现
- 3–4：人物介绍单薄（一句话带过），几乎不提访谈现场
- 0–2：无人物介绍，读者不知道"这场对话为什么重要"

## 语言组（25 分）

### 7. 口语自然度（10 分）
- 9–10：通篇口语（"你想想""说白了"等引导词自然分布、不机械重复），无书面腔、无翻译腔、无 AI 套话（"总而言之""综上所述"）
- 7–8：整体口语化，少量段落滑入书面语
- 4–6：口语引导词存在但分布机械（如每段开头固定"你看"），或中后段明显书面化
- 0–3：大面积书面语，不适合口播
（参考 lint 统计中的互动词密度数据，但以读感为准。）

### 8. 节奏与听感（8 分）
- 7–8：短句为主但长短交错有呼吸感，过渡词自然衔接（"接下来""更关键的是"），设问/反问/强调重复运用得当
- 5–6：节奏尚可，但存在大段每句一行的碎片化短句（单调），或个别超长句
- 3–4：节奏单一（通篇等长短句，或通篇长句），过渡生硬
- 0–2：无节奏设计，不适合朗读
（参考 lint 统计中的句长分布数据。注意：句子全部 <20 字并非满分条件——单调的碎片化短句要扣分。）

### 9. 术语白话化与数字可感（7 分）
- 6–7：每个专业术语首次出现都有类比/举例/拆解式白话解释；关键数字换算成可感知量级（"换成人民币 2100 多亿"）
- 4–5：多数术语有解释，少数裸奔；数字偶有可感化
- 2–3：术语解释覆盖不到一半，或解释生硬（直接给定义而非类比）
- 0–1：术语大面积裸奔，数字无换算

## 判定规则

- `total_score` = 各维得分之和（信息覆盖度缺参照清单时：总分 = 其余维度得分 / 80 × 100，四舍五入保留 1 位小数）
- verdict 规则：`total_score ≥ 80` 且 **无任何单维得分低于该维满分的 60%** → `pass`；否则 → `needs_revision`
- 每个未达标维度必须产出至少 1 条修订指令（`revision_directives`），指令需定位到具体小节并给出可执行的改法

## 变更记录

- v3（2026-06）：自 v2 六维体系升级。新增「信息覆盖度」「信息忠实度」（此前不可见的最大盲区——输入截断问题）；外部知识维度增加可溯源与深度叙事要求；「口语化节奏」拆分为口语自然度/节奏听感/术语数字三维；明确单调碎片短句扣分；引入分数锚点与证据引用要求。
- v2 及以前：见 `docs/goal目标制定/差距分析-三篇产出vs黄金样本.md`
````

遵循项目 prompt 文件约定（`# System Prompt` / `# User Prompt` 分节，由 `load_prompt("judge_score")` 解析）。**将下面内容原样写入**：

````markdown
# System Prompt

你是一位严格的中文口播稿审稿编辑。你的任务是按照给定的评分标准（rubric）对一篇「英文播客访谈 → 中文口播解说稿」逐维打分。

硬性要求：
1. **每个维度的打分必须引用稿件原文片段作为证据**（evidence 字段，引用 1-3 个最能支撑该分数的片段，每段 ≤50 字）
2. **就低不就高**：介于两档之间时取低档。你的价值在于发现问题，不在于给出好看的分数
3. 对每个未达标维度（得分 < 该维满分的 60%），必须给出至少 1 条修订指令：定位到具体小节（用稿件中该节的标签或开头句描述位置），说明问题，给出可执行的改法

{
  "rubric_version": "v3",
  "total_score": 0.0,
  "dimensions": [
    {
      "dimension": "信息覆盖度",
      "score": 0.0,
      "max_score": 20,
      "evidence": ["引用片段1", "引用片段2"],
      "issues": ["问题描述"]
    }
  ],
  "revision_directives": [
    {
      "target": "「第二条 GPU 时间幻觉」一节",
      "problem": "该节只有一句话数据型外部知识，缺深度叙事",
      "instruction": "在 Alchian-Allen 效应处补充一段 80-150 字的真实历史案例叙事，需标注来源"
    }
  ],
  "verdict": "pass"
}

5. dimensions 数组必须包含 rubric 中的全部维度，顺序与 rubric 一致
6. 若用户输入中标明「无参照论点清单」，则「信息覆盖度」维度的 score 填 -1、evidence 填空数组，并按 rubric 的折算规则计算 total_score

# User Prompt

请按以下评分标准对口播稿打分。

## 评分标准

{rubric}

## 参照论点清单（用于评估信息覆盖度）

{reference_points}
````

### 1.3 数据模型 `src/podlator/steps/models.py`（追加）

```python
class DimensionScore(BaseModel):
    """单一维度的评分结果。"""

    dimension: str
    score: float          # 信息覆盖度缺参照时为 -1（不计分标记）
    max_score: float
    evidence: list[str] = Field(default_factory=list)
    issues: list[str] = Field(default_factory=list)


class RevisionDirective(BaseModel):
    """给写手的定点修订指令（M5.4 的修订循环将直接消费它）。"""

    target: str           # 定位描述，如「第二条 GPU 时间幻觉」一节
    problem: str
    instruction: str


class JudgeReport(BaseModel):
    """LLM judge 的完整评分报告。"""

    rubric_version: str
    total_score: float
    dimensions: list[DimensionScore]
    revision_directives: list[RevisionDirective] = Field(default_factory=list)
    verdict: Literal["pass", "needs_revision"]


class LintStats(BaseModel):
    """程序化文本统计（零 LLM 成本）。"""

    char_count: int                    # 中文字数（复用 douyin_script._count_chinese_chars 的逻辑，抽到公共处）
    sentence_count: int
    long_sentence_ratio: float         # >40 字句子占比
    short_sentence_ratio: float        # <15 字句子占比
    interaction_density: float         # 互动词次数 / (字数/300)，即"每 300 字互动次数"
    markdown_heading_count: int        # ^#{1,6}\s 行数
    meta_text_detected: bool           # 开头是否命中 meta 模式
    speaker_label_count: int           # "Speaker A/B" / "说话人A" 残留次数
    truncation_suspected: bool         # 非空稿件结尾未落在终止符（。！？…」"）→ 疑似被截断
    word_count_target: int | None      # 目标字数（未知时 None）
    word_count_ok: bool | None         # 实际在目标 ±10% 内？（无目标时 None）
```

### 1.4 rubric 加载函数 `src/podlator/prompts/__init__.py`（追加）

```python
def load_rubric(version: str = "v3") -> str:
    """加载评分标准全文（用于注入 judge prompt）。

    Raises:
        FileNotFoundError: 指定版本的 rubric 文件不存在。
    """
    path = PROMPTS_DIR / f"rubric_{version}.md"
    if not path.exists():
        available = sorted(p.stem for p in PROMPTS_DIR.glob("rubric_*.md"))
        raise FileNotFoundError(f"Rubric {version!r} 不存在。可用版本: {available}")
    return path.read_text(encoding="utf-8")
```

## Phase 2: 程序 lint `src/podlator/steps/lint_script.py`

**设计原则**：凡是确定性可查的，绝不花 LLM token。lint 产出两类结果：(a) 统计数据喂给 judge 参考；(b) 硬伤直接生成修订指令（不需要 judge 也能断定的问题）。

> **截断探针 = 静默截断的永久跳闸器**。M5.0 在源头（provider + assign-speakers）修复了三个边界的静默截断；这里的 `truncation_suspected` 是**最后一道防线**——无论未来哪个环节又把稿子截断了，只要它不以正常终止符收尾，lint 就当场判硬伤、拦在发布之前。源头修复 + 末端跳闸，双保险。

### 2.1 实现

```python
"""Step: 口播稿程序化检查（零 LLM 成本）。

检查项：
- 中文字数 vs 目标（±10%）
- Markdown 标题残留（^#{1,6}\\s）
- Meta 文字（开头 200 字内命中「好的，」「以下是」「下面我们」「交给我」等模式）
- Speaker 标签残留（Speaker [A-Z] / 说话人[A-Z甲乙丙]）
- 句长分布（按 。！？切句；>40 字为长句，<15 字为短句）
- 互动词密度（词表见下，每 300 字次数）
- 截断探针（非空稿件结尾未落在 。！？…」"）等终止符 → 疑似被生成上限/输入截断）
"""

INTERACTION_WORDS = [
    "你想", "你看", "你猜", "说白了", "说实话", "说真的",
    "听明白了吧", "你听", "我认为", "我觉得", "对吧", "是不是",
]

META_PATTERNS = [r"^好的[，,]", r"^以下是", r"^下面我们", r"交给我", r"^这是一篇"]


def lint_script(
    script: str,
    *,
    target_words: int | None = None,
) -> tuple[LintStats, list[RevisionDirective]]:
    """对口播稿做程序化检查。

    Returns:
        (统计数据, 硬伤修订指令列表)。硬伤包括：Markdown 标题、meta 文字、
        speaker 标签、字数偏离 >10%。
    """
```

硬伤 → 指令的映射（写死，不要发挥）：

| 检出 | RevisionDirective.instruction |
|---|---|
| markdown_heading_count > 0 | "删除全部 Markdown 标题行，改用口语过渡词衔接（'你看''接下来''聊到这里'）" |
| meta_text_detected | "删除开头的引导语，直接从标题和正文开始" |
| speaker_label_count > 0 | "把 Speaker A/B 等标签改写为自然称呼（人名或'主持人''嘉宾'）" |
| truncation_suspected | "稿件疑似被截断（未以 。！？…」等终止符收尾）：定位末段排查生成上限/输入截断，**重新生成而非续写**（续写会破坏结尾收束）" |
| word_count_ok is False（不足） | "当前 N 字低于目标下限 M 字：挑写得最薄的主题定点扩写（举例/背景/点评），禁止在结尾后追加新段落" |

```bash
  [-o report.json]          # 报告输出路径（默认 <稿件名>.review.json）
```

行为：调用 `evaluate_script`，落盘 JSON 报告（`JudgeReport` + `LintStats` 合并为一个对象 `{judge: ..., lint: ...}`），并在终端打印一张维度分数表（rich table，与现有 CLI 输出风格一致）+ verdict。退出码：pass → 0，needs_revision → 0（评分是信息不是失败），文件不存在/解析失败 → 1。

### 4.2 Step Registry 注册

`steps/registry.py` 注册 `lint_script` 与 `evaluate_script`（input_type=str 用占位说明，参考现有条目写法）。

### 5.3 校准失败的处理路径（按顺序，最多走到第 3 步）

1. **检查解析与折算**：是不是 -1 折算/求和 bug（代码问题先排除）
