# M5.2 — 全文消化（digest，消灭输入截断边界 C）

> **执行者注意**：开始前先读 `docs/tasks/EXECUTION-FRAMEWORK.md`、`CLAUDE.md`（第 7、9、13 章）、`docs/tasks/M5-overview.md`、本任务书。
> 本任务书包含所有设计决策。遇到未覆盖的情况，停下来在完成报告中说明，**不要自行猜测**。
>
> 一句话目标：把完整 transcript **分段精读成结构化「素材笔记」**，让 blueprint/finalize 不再吃被 `DEFAULT_MAX_INPUT_CHARS=36000` 截断的原文，而是吃覆盖访谈全程的笔记。这是 M5-overview「横切病症」表里的**输入面 C**——本次要彻底消灭的静默截断。

---

## 0. 背景与边界

`douyin_script.py` 的 `_format_transcript_for_douyin` 在 36000 字符处**静默截断**，12 期素材正文实测 58,746–137,080 字符，每期 40%–75% 访谈被悄悄丢弃，蓝图和成稿只基于访谈前段写成。

**本任务的解法**（map-reduce）：
- 新增 `digest` 步骤：全文按段落边界分块（带重叠），每块用便宜模型（DeepSeek）精读成「素材笔记」（核心论点 + 原话引用 + 数字/金额/日期 + 待白话化术语），落盘 `*.digest.json`。
- blueprint / finalize 的 `{content}` 槽位：从「截断原文」换成「素材笔记全集」（总量约 6–10k 中文字符，任何模型都舒适，且覆盖全程）。
- 截断逻辑保留但**触发即 `log.warning`**（复用 M5.0 精神，不再静默）；`max_input_chars` 默认 36000 → 160000。

**复用 M5.0 成果**：digest 每块调用 DeepSeek 后检查 `result.finish_reason`（M5.0 已在 provider 层落地），笔记自身被截断时告警重试。

**复用 M5.1 成果**：验收用 `evaluate_script`（M5.1）做新旧蓝图 A/B 评分，证明覆盖度真的提升。

### 范围（明确不要做的事）

- ❌ **不做** research 联网查证（M5.3）——digest 只消化访谈**内部**内容，不补外部知识。
- ❌ **不做**审稿循环 / 修订（M5.4）。
- ❌ **不动** rubric / judge / lint（M5.1 已完成，本任务只**调用**它们）。
- ❌ **不改** blueprint 的「外部知识补充点」为结构化研究问题清单——那是 M5.3 的 prompt 改造。本任务的 blueprint/finalize prompt 改动**只限 `{content}` 注入的内容来源**，不动其它结构。
- ❌ **不在** unit / integration 层调真实 API（见第「开发期真实 API 使用规约」节——真实调用只允许在 smoke 层）。

## Phase 1: 数据模型 + digest prompt

### 1.1 `src/podlator/steps/models.py`（追加）

```python
# -- Digest 相关模型（M5.2）--


class DigestQuote(BaseModel):
    """素材笔记中的一条原话引用（保留 speaker + 时间点，供下游佐证）。"""

    speaker: str
    text: str  # 原话（可短引，不必逐字整段）
    time: float = Field(description="该原话起始时间点（秒）")


class DigestDataPoint(BaseModel):
    """一个值得保留的数字 / 金额 / 日期。"""

    value: str  # 如 "$95.2B" / "8760 小时" / "2017 年"
    context: str  # 这个数字说明什么（一句话）
    time: float = Field(description="出现时间点（秒）")


class DigestChunk(BaseModel):
    """单个分块的素材笔记。chunk_index/start/end 由代码填，其余由 LLM 产出。"""

    chunk_index: int
    start_time: float  # 本块第一条 segment 的 start
    end_time: float  # 本块最后一条 segment 的 end
    key_points: list[str] = Field(default_factory=list)  # 本块核心论点（中文要点）
    quotes: list[DigestQuote] = Field(default_factory=list)
    data_points: list[DigestDataPoint] = Field(default_factory=list)
    terms: list[str] = Field(default_factory=list)  # 待白话化术语（原样保留英文/专业词）


class DigestDocument(BaseModel):
    """完整素材笔记 — step 层标准格式，落盘 *.digest.json。"""

    schema_version: int = Field(default=1)
    source_transcript: str | None = Field(default=None)  # 来源 transcript 路径
    title: str | None = Field(default=None)
    total_duration_seconds: float | None = Field(default=None)
    chunks: list[DigestChunk] = Field(default_factory=list)
```

### 1.3 `src/podlator/prompts/digest_chunk.md`（新建）

# System Prompt

你是播客访谈的「素材精读员」。你的任务**不是翻译、不是写解说稿**，而是把一段英文访谈精读成结构化的中文「素材笔记」，供下游写作模型取用。

精读要求：
1. **核心论点**（key_points）：提炼本段真正有信息量的观点，用中文要点表述，不要流水账、不要逐句翻译。

  "terms": ["H100", "CoWoS"]
}

若本段没有某一类内容，对应数组留空。不要编造原文里没有的信息。

# User Prompt

请精读下面这段访谈（已标注说话人和时间点），产出结构化素材笔记 JSON。

## 访谈片段

{segments_text}

## 输出（只输出 JSON 对象本身）
````

## Phase 2: digest step `src/podlator/steps/digest_transcript.py`（新建）

**设计原则**：digest 是纯 step（只接 transcript + provider，返回 DigestDocument，IO 由 CLI 做）。分块在段落（segment）边界，带重叠保证跨块论点不丢。

### 2.1 公开签名

```python
async def digest_transcript(
    transcript: TranscriptDocument,
    *,
    provider_name: str | None = None,   # None → settings.llm_provider_digest（deepseek）
    settings: Settings | None = None,
    chunk_chars: int = 30000,
    overlap_chars: int = 2000,
) -> DigestDocument:
    """全文分块精读 → DigestDocument。

    - 按 segment 累计字符数分块（在 segment 边界切，不切碎句子），相邻块重叠 overlap_chars
    - 每块用便宜模型精读，产出 DigestChunk
    - 并发处理所有块（asyncio.gather，仿 assign_speakers）
    - 单块失败（JSON 不合法）：重试 1 次仍失败 → log.warning + 产出空内容的 DigestChunk
      （保留该块时间范围，让"尾部进入过视野"可观察），不让一块拖垮整体
    - 复用 M5.0：result.finish_reason == "length" → log.warning("digest_chunk_truncated", ...)
    """
```

### 2.2 关键内部函数（给出签名 + 职责，实现细节执行者补全）

```python
def _chunk_segments(
    segments: list[TranscriptSegmentModel],
    chunk_chars: int,
    overlap_chars: int,
) -> list[list[TranscriptSegmentModel]]:
    """按累计 text 字符数在 segment 边界分块，相邻块按字符数重叠。
    返回每块的 segment 子列表。短 transcript（总字符 <= chunk_chars）→ 单块。"""


def _format_chunk_for_prompt(segments: list[TranscriptSegmentModel]) -> str:
    """格式化为 prompt 行：'[123.40 - 130.00] PAUL: 原话'（含时间点，供 quotes/data 取 time）。
    可复用 assign_speakers._format_segment_for_prompt 的风格。"""


def _parse_digest_chunk(content: str) -> dict | None:
    """剥离 ```json 包裹 → json.loads → 返回 dict；失败返回 None。
    可复用 evaluate_script._parse_json_block 的剥离逻辑（抽公共或照写）。"""


async def _digest_one_chunk(
    chunk: list[TranscriptSegmentModel],
    chunk_index: int,
    provider_name: str,
    settings: Settings,
) -> DigestChunk:
    """调一块的 LLM，解析为 DigestChunk；失败重试 1 次再失败 → 空 DigestChunk（保留时间范围）。
    start_time = chunk[0].start，end_time = chunk[-1].end（代码填，不信任 LLM）。"""
```

### 2.3 prompt 注入的「素材笔记全集」格式化器（本文件内，douyin_script 会 import）

```python
def format_digest_for_prompt(digest: DigestDocument) -> str:
    """把 DigestDocument 渲染成注入 blueprint/finalize {content} 槽位的纯文本笔记。

    输出形如（按 chunk 时间顺序，标出时间点以便下游聚合跨时间素材）：

    ## 素材笔记（覆盖 00:00–58:30 全程）

    ### [02:03] 段落 1
    核心论点：
    - ...
    原话：
    - PAUL（02:10）：「...」
    数字与事实：
    - $95.2B —— 英伟达 2024 数据中心营收（03:20）
    待白话化术语：H100、CoWoS
    ...
    """
```

> 设计意图：笔记里保留 speaker + 时间点，finalize 才能「跨时间轴聚合原文素材」（rubric 结构维度的要求），并据 quotes 做忠实转述、据 data_points 做数字可感化。

### 2.4 日志（按 CLAUDE.md 7.3）

- 入口 `log.info("digest_started", segments=..., total_chars=..., chunk_chars=...)`
- 分块后 `log.info("digest_chunks_created", num_chunks=..., chunk_char_sizes=[...])`
- 每块 LLM 调用走 provider 自带的 `llm_completed`（带 cost/tokens/duration），digest 层**不要在循环里逐块再 log 一遍**（CLAUDE.md 7.5 禁止循环内逐迭代 log）
- 出口 `log.info("digest_completed", num_chunks=..., total_key_points=..., total_quotes=..., total_data_points=...)`

## Phase 3: 接入 douyin_script（`{content}` 改吃笔记 + 截断告警）

**最小改动原则**：digest 由 CLI 运行并传入；`generate_douyin_script` 只做「有 digest 用笔记、没 digest 用（提高上限的）原文」的纯消费判断。

### 3.1 `src/podlator/steps/douyin_script.py` 改动

```python
DEFAULT_MAX_INPUT_CHARS = 160000   # 从 36000 提到 160000（覆盖最长一期 137,080 字符）
```

`generate_douyin_script` 新增参数：

```python
async def generate_douyin_script(
    transcript: TranscriptDocument,
    *,
    ...,
    digest: DigestDocument | None = None,       # 新增：有则注入笔记，无则回退原文
    blueprint_path: Path | None = None,         # 新增：传入则把蓝图落盘（可观察性，M5-overview 要求）
    max_input_chars: int = DEFAULT_MAX_INPUT_CHARS,
    ...,
) -> str:
```

主流程里 `content` 的来源改造：

```python
if digest is not None:
    from podlator.steps.digest_transcript import format_digest_for_prompt
    content = format_digest_for_prompt(digest)
    logger.info("douyin_using_digest", chunks=len(digest.chunks), notes_chars=len(content))
else:
    content = _format_transcript_for_douyin(transcript.segments, max_input_chars)
```

`_format_transcript_for_douyin` 截断分支改造（**消灭静默截断**）：触发截断时，把现有那行 `... (后续还有 N 条片段，已截断) ...` 保留的同时，加：

```python
logger.warning(
    "transcript_truncated",
    dropped_segments=remaining,
    kept_chars=char_count,
    max_input_chars=max_chars,
    hint="正文超出 max_input_chars，建议走 digest 模式（--digest-mode map/auto）",

```

两段式里生成 blueprint 后，若 `blueprint_path` 非空：`write_markdown(blueprint_path, blueprint)` + `log.info("blueprint_persisted", path=..., size_bytes=...)`。

> **为什么用 `blueprint_path` 参数而不是改返回类型**：`generate_douyin_script` 现返回 `str`，被 CLI 和多个测试依赖。加可选落盘参数是满足「蓝图落盘」可观察性要求的最小侵入改法。**M5.3 会把 blueprint/finalize 拆成独立公共 step**（research 要插在两者之间、M5.4 审稿循环也要用），届时再重构，本任务不提前做。

### 4.1 新增 `podlator digest`（独立步骤，便于调试 + 落盘）

### 4.2 `douyin-script` 与 `pipeline-douyin` 增加 `--digest-mode`

新增选项（两个命令都加）：

```python
digest_mode: Annotated[str, typer.Option(
    "--digest-mode", help="auto(默认,>50k字符走map-reduce) | full(直喂原文) | map(强制消化)",
)] = "auto",
```

编排逻辑（放 CLI 的 `_*_cmd` 里，新增一个小 helper）：

```python
async def _maybe_digest(
    doc: TranscriptDocument, mode: str, settings: Settings, digest_out: Path | None
) -> DigestDocument | None:
    """按 digest_mode 决定是否消化。
    - full → None（走原文，max_input_chars 已提到 160k + 截断告警）
    - map  → 必消化
    - auto → 正文 > 50000 字符则消化，否则 None
    消化时落盘 digest_out（*.digest.json，可观察性），并 log。
    """
```

`pipeline-douyin` 步序变成 `[1/4] parse → [2/4] assign → [3/4] digest（按 mode）→ [4/4] douyin-script`；digest 落盘 `<output>.digest.json`、blueprint 落盘 `<output>.blueprint.md`（把 `blueprint_path` 传进 `generate_douyin_script`）。`douyin-script` 同理（它的输入是 transcript，digest 落盘 `<output>.digest.json`）。

> 全自动直通，落盘**不是**人工暂停点（M5-overview 决策：蓝图不再人工审核，仅落盘）。
