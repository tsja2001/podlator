# M1.4 — 文件转换型 Step CLI + 可组合 LangGraph Workflow

> **执行前先读 `docs/tasks/EXECUTION-FRAMEWORK.md`。**
> **依赖 M1.1 + M1.2 + M1.3 完成。** 当前 `podlator run <url>` 已能跑完整 pipeline。

---

## 目标

把当前“一条 CLI 跑完整 pipeline”的设计，重构为：

1. **独立 step 函数**：每一步都是明确的文件转换能力，例如 `audio.mp3 -> transcript.json`。
2. **单步 CLI**：每个 step 都能用 CLI 独立调用，输入输出通过文件参数表达。
3. **LangGraph workflow 编排层**：完整 pipeline 不再直接承载业务逻辑，而是把这些 step 串起来；未来可通过 workflow 配置改变节点排列组合。

重构后，完整流程仍然可用：

```bash
uv run podlator run "https://www.youtube.com/watch?v=XXXXX"
```

但调试和扩展时可以这样用：

```bash
uv run podlator download "https://www.youtube.com/watch?v=XXXXX" -o episode.mp3
uv run podlator transcribe episode.mp3 -o transcript.json
uv run podlator parse-srt subtitles.srt -o transcript.json
uv run podlator assign-speakers transcript.json -o transcript.speakers.json
uv run podlator split transcript.json -o chapters.json
uv run podlator render transcript.json --chapters chapters.json --mode summary -o summary.md
uv run podlator render transcript.json --chapters chapters.json --mode full -o full-translation.md
uv run podlator polish summary.md -o brief.md
```

---

## 核心判断

这次拆分不应该以 `data/artifacts/{task_id}/` 作为主接口。

`artifacts` 是完整 pipeline 的运行记录，适合排查问题；但独立 CLI 的主接口应该是**业务文件**：

- URL 或媒体链接；
- 音频文件；
- SRT 字幕文件；
- 转录 JSON；
- 章节 JSON；
- 草稿 Markdown；
- 最终 Markdown。

这样每个命令都可以脱离完整任务运行，未来业务变化时也能自由排列组合。

---

## LangGraph 在这里的角色

LangGraph 不负责替代 CLI，也不应该让 CLI 强依赖完整 graph state。

推荐职责划分：

```text
src/podlator/steps/       # 真正的业务能力：文件/结构化数据 -> 文件/结构化数据
        ↑        ↑
        │        │
src/podlator/cli.py       # 人手动调用单步工具
src/podlator/graph/       # LangGraph 自动编排 steps
```

LangGraph 适合解决：

- 长流程自动编排；
- 条件分支，例如 STT 已带说话人时跳过 diarize；
- checkpoint / resume，失败后不重跑慢步骤；
- interrupt，章节切分后暂停给人检查；
- subgraph，把局部流程封成可复用子流程；
- workflow 配置化，根据 YAML/JSON 决定节点排列组合。

本任务只做本地文件型 step 和 CLI，并为后续动态 workflow 留好接口；不一次性实现完整 workflow DSL，避免范围过大。

## 目标架构

### 1. Core Steps

新增 `src/podlator/steps/`，每个 step 是可测试、可复用的业务函数。

建议文件：

```text
src/podlator/steps/
├── __init__.py
├── models.py
├── io.py
├── download.py
├── transcribe.py
├── parse_srt.py
├── assign_speakers.py
├── split_chapters.py
├── render_chinese.py
└── polish.py
```

职责：

- `models.py`：定义文件格式模型，例如 `TranscriptDocument`、`ChapterDocument`。
- `io.py`：读写 JSON / Markdown。
- `download.py`：URL -> audio file + metadata JSON。
- `transcribe.py`：audio file -> transcript JSON，通过外部 `speech-transcriber` CLI 完成语音转文字。
- `parse_srt.py`：SRT subtitle file -> transcript JSON。
- `assign_speakers.py`：transcript JSON -> transcript JSON with inferred speakers。
- `split_chapters.py`：transcript JSON -> chapters JSON。
- `render_chinese.py`：transcript JSON + chapters JSON -> markdown，支持 `summary` / `full` 模式。
- `polish.py`：draft markdown -> polished markdown。

### 2. CLI

CLI 只做：

- 解析参数；
- 读取输入文件；
- 调用 step；
- 写输出文件；
- 打印简短结果。

CLI 不应该复制 Provider 调用逻辑，也不应该直接拼大段 prompt。

### 3. LangGraph

现有 graph node 改为调用 steps。

例如：

```text
transcribe node:
  从 state.audio_path 取音频路径
  调用 steps.transcribe.transcribe_audio(...)
  把结果写回 state.transcript_segments / transcript_text
```

后续可以增加：

```bash
uv run podlator workflow run workflow.yaml
```

示例 workflow：

```yaml
input:
  audio: episode.mp3
steps:
  - transcribe
  - split
  - render:
      mode: full
  - polish
output:
  markdown: full-polished.md
```

## 文件格式约定

文件格式要稳定，CLI 和 LangGraph 都围绕这些格式交互。

### Transcript JSON

```json
{
  "schema_version": 1,
  "source": {
    "audio_path": "episode.mp3",
    "source_url": "https://www.youtube.com/watch?v=XXXXX",
    "title": "Episode Title",
    "duration_seconds": 1234.5
  },
  "provider": {
    "name": "deepgram",
    "cost_usd": 0.0123
  },
  "text": "Full transcript text...",
  "segments": [
    {
      "index": 0,
      "start": 0.0,
      "end": 5.25,
      "speaker": "speaker_0",
      "text": "Welcome to the show.",
      "confidence": 0.98
    }
  ]
}
```

### Chapters JSON

```json
{
  "schema_version": 1,
  "source_transcript": "transcript.json",
  "chapters": [
    {
      "index": 0,
      "title": "开场与主题介绍",
      "start": 0.0,
      "end": 120.5,
      "segment_indices": [0, 1, 2, 3]
    }
  ]
}
```

### Render 输出

`render` 输出 Markdown，但模式不同：

- `summary`：中文精简摘要；
- `full`：中文全文翻译；
- `bullets`：可选，后续再做，本任务只预留模式，不实现。

本任务实现 `summary` 和 `full` 两种模式。

## CLI 设计

### `download`

```bash
uv run podlator download "https://www.youtube.com/watch?v=XXXXX" -o episode.mp3 --metadata metadata.json
```

输入：

- URL。

输出：

- 音频文件；
- 可选 metadata JSON。

### `transcribe`

```bash
uv run podlator transcribe episode.mp3 -o transcript.json
```

输入：

- 音频文件路径。

输出：

- Transcript JSON。

可选参数：

```bash
--provider tencent_cloud
--language en
--diarize / --no-diarize
```

Podlator 不再内嵌具体语音转文字服务。

语音转文字能力统一调用独立项目：

```text
/Users/yangzhuoran/program/speech-transcriber
```

该项目已经封装腾讯云 ASR / COS，并对外提供稳定 CLI：

```bash
uv run speech-transcriber transcribe /path/to/audio.mp3 --provider tencent_cloud --output json
```

Podlator 作为消费方项目，只负责调用这个 CLI 并解析 stdout JSON，不直接调用腾讯云 ASR / COS SDK，也不在本项目内继续维护腾讯云转写 Provider。

推荐调用方式：

```bash
uv run --project /Users/yangzhuoran/program/speech-transcriber \
  speech-transcriber transcribe episode.mp3 \
  --provider tencent_cloud \
  --output json
```

`speech-transcriber` JSON 输出结构：

```json
{
  "text": "...",
  "segments": [
    {
      "start": 0.0,
      "end": 1.0,
      "text": "...",
      "speaker": "SPEAKER_0",
      "confidence": null
    }
  ],
  "provider": "tencent_cloud",
  "duration_seconds": 1.0,
  "has_diarization": true,
  "metadata": {}
}
```

Podlator 的 `steps/transcribe.py` 负责把这份 JSON 映射成 `TranscriptDocument`。

### `parse-srt`

```bash
uv run podlator parse-srt subtitles.srt -o transcript.json
uv run podlator parse-srt subtitles.srt -o transcript.json --assign-speakers
```

输入：

- SRT 字幕文件。

输出：

- Transcript JSON。

行为：

- 解析 SRT 序号、时间范围、字幕文本。
- 生成 `segments`，每条字幕作为一个 segment。
- `speaker` 默认写 `null`。
- `provider.name` 使用 `srt`。
- `--assign-speakers` 打开时，在解析后继续调用 `assign_speakers` step，用 LLM 推断说话人标签。

### `assign-speakers`

```bash
uv run podlator assign-speakers transcript.json -o transcript.speakers.json
```

输入：

- Transcript JSON。

输出：

- 带 `speaker` 的 Transcript JSON。

行为：

- 只补充或修正 `segments[*].speaker`。
- 不改写 `segments[*].text`。
- 不改变 `start/end`。
- 不做章节切分、翻译、摘要或润色。

说明：

- SRT 通常没有可靠说话人信息，只能通过上下文和语言线索让 LLM 推断，因此结果要视为“辅助标注”，不是 STT diarization 那种声纹级分离。
- CLI 用显式参数控制是否做说话人推断，默认 `parse-srt` 只解析字幕，不额外调用 LLM。

### `split`

```bash
uv run podlator split transcript.json -o chapters.json
```

输入：

- Transcript JSON。

输出：

- Chapters JSON。

注意：`split` 只做章节切分，不翻译、不摘要、不润色正文。

### `render`

```bash
uv run podlator render transcript.json --chapters chapters.json --mode summary -o summary.md
uv run podlator render transcript.json --chapters chapters.json --mode full -o full-translation.md
```

输入：

- Transcript JSON；
- Chapters JSON。

输出：

- Markdown。

模式：

- `summary`：沿用当前 `summarize_chapter` 思路，按章节生成中文精简摘要。
- `full`：新增全文翻译模式，按章节输出完整中文翻译，不压缩信息。

### `polish`

```bash
uv run podlator polish summary.md -o brief.md
```

输入：

- Markdown 草稿。

输出：

- 润色后的 Markdown。

### `run`

保留现有完整命令：

```bash
uv run podlator run "https://www.youtube.com/watch?v=XXXXX"
```

内部可以继续走 LangGraph，但 graph node 应逐步改为调用 `steps`。

## 章节切分时间戳修正

### 问题

当前 `chapter_split` 给 LLM 的是纯文本：

```text
Welcome to the show. Today we talk about...
```

但要求 LLM 输出 `start/end`。没有时间戳时，模型只能估算，导致边界不准。

### 修正

`split` step 从 Transcript JSON 的 `segments` 生成带时间戳的 prompt 输入：

```text
[0.00 - 5.25] speaker_0: Welcome to the show.
[5.25 - 12.40] speaker_1: Thanks for having me.
```

Prompt 必须明确：

- 只根据给定时间戳切章节；
- `start` 使用或贴近某一 segment 的开始秒；
- `end` 使用或贴近某一 segment 的结束秒；
- 不总结、不翻译、不润色、不输出原文片段；
- 只输出 JSON。

这保证 `chapters.json` 是纯结构产物，不混入摘要或正文改写。

### 2.1 `steps/transcribe.py`

核心函数：

```python
async def transcribe_audio(
    audio_path: Path,
    *,
    provider_name: str | None = None,
    language: str = "en",
    diarize: bool = True,
    speech_transcriber_project_dir: Path | None = None,
```

实现：

- 解析 stdout JSON，并映射为 `TranscriptDocument`。
- 当外部 CLI 返回非 0 exit code 时，抛出可操作错误，并包含 stderr 前 1000 字符。
- 当 stdout 不是合法 JSON 或缺少 `text` / `segments` 时，抛出 schema 错误。

现有 `graph/nodes/transcribe.py` 后续改为调用这个函数。

```env

```

当前项目中已有的 `podlator.providers.stt.*` 可以在本任务中停止作为 active path 使用；是否删除旧代码可单独评估。如果为了降低改动风险先保留旧文件，必须在文档和代码注释里标明它们不再是默认转写入口。

### 2.2 `steps/parse_srt.py`

核心函数：

```python
def parse_srt_file(
    srt_path: Path,
    *,
    source_url: str | None = None,
    title: str | None = None,
) -> TranscriptDocument:
    ...
```

实现：

- 解析标准 SRT block：
  - 序号行；
  - `HH:MM:SS,mmm --> HH:MM:SS,mmm` 时间行；
  - 一行或多行字幕文本。
- 合并同一 block 的多行字幕文本。
- 将时间转为秒。
- 输出 `TranscriptDocument`：
  - `provider.name = "srt"`；
  - `provider.cost_usd = 0.0`；
  - `segments[*].speaker = None`；
  - `text` 为所有字幕文本拼接结果。

边界要求：

- 空 SRT 返回可操作错误。
- 时间格式非法返回可操作错误，并带 block 序号。
- 解析函数不调用 LLM，不做说话人推断。

### 2.3 `steps/assign_speakers.py`

核心函数：

```python
async def assign_speakers(
    transcript: TranscriptDocument,
    *,
    provider_name: str | None = None,
) -> TranscriptDocument:
    ...
```

实现：

- 把 segments 格式化为带 index、时间戳和文本的 prompt。
- 调用 LLM 返回 JSON：

```json
[
  {"index": 0, "speaker": "SPEAKER_A"},
  {"index": 1, "speaker": "SPEAKER_B"}
]
```

- 只按 index 写回 `speaker` 字段。
- 如果 LLM 缺少某些 index，原 segment 保持不变。
- 如果 LLM 返回不存在的 index，忽略并记录 warning。
- 不改写文本和时间戳。

Prompt 要明确：

- 你只能分配 speaker 标签；
- 不能改写字幕文本；
- 不能翻译、摘要或润色；
- 对无法判断的片段使用前后文最可能的 speaker，仍无法判断则使用 `UNKNOWN`。

### 2.4 `steps/split_chapters.py`

核心函数：

这里解决章节切分时间戳问题。

- `render transcript.json --chapters chapters.json --mode summary -o summary.md` 能写 Markdown；
- `render --mode full` 能走全文翻译 prompt；
- 缺少输入文件时返回非 0 退出码。
